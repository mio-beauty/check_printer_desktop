# Warehouse Queue (desktop) — как проверить

Этот документ описывает минимальный QA сценарий для экрана **“Очередь склада”** в desktop‑клиенте.

## Требования

- Backend доступен (например `https://printer.backend.miobeauty.uz`).
- В backend есть пользователь с ролью `picker` (или любая роль, которой разрешены `/api/warehouse/*`).
- Desktop подключается к backend по Socket.IO (индикаторы `socket: ok` и `join: ok`).

## Сценарий (MVP)

1) Запусти desktop‑клиент.
2) Перейди в вкладку **“Склад”** (в верхней кастомной шапке).
3) Если попросит вход:
   - введи `phone` и `password`
   - нажми **“Войти”**
4) Убедись, что виден статус **Онлайн** (если оффлайн — действия должны быть заблокированы).
5) В списке:
   - отображаются `picking_status` и прогресс `picked/ordered`
   - виден `Печатался/Не печатался`
   - видны `клиент/телефон/позиций/сумма` (если есть в snapshot)
6) Проверь фильтры:
   - `К сборке` / `В сборке` / `Собран` / `Частично`
7) Проверь поиск:
   - введи часть номера / `order_id` / телефон
   - список обновляется с задержкой (debounce ~350ms), не подвисает
8) Нажми **“Открыть”** или клик по номеру — открывается экран деталей заказа (MVP).
9) Если сессия не начата — нажми **“Начать сборку”**:
   - backend создаёт `pick_session` и `pick_items` из snapshot `order_data.items[]`

## Offline поведение

- Если `socket: нет` или `join` не `ok`:
  - показываем бейдж **Оффлайн**
  - кнопки `Начать/Продолжить/Открыть` должны быть disabled
