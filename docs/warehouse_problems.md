# Warehouse Problems (desktop) — как проверить

Этот документ описывает минимальный QA сценарий для экрана **“Проблемы”** в desktop‑клиенте (статусы `PARTIALLY_PICKED`, `PICK_FAILED`).

## Требования

- Backend доступен и отвечает на:
  - `GET /api/warehouse/orders?problems=1`
  - `GET /api/warehouse/reasons`
  - `GET /api/warehouse/orders/<id>/events`
- В backend есть пользователь (role `picker` или выше), у которого есть доступ к `/api/warehouse/*`.

## Сценарий (MVP)

1) Открой заказ и начни сборку.
2) Отсканируй часть позиций.
3) Нажми **“Завершить частично”**:
   - причина обязательна
   - комментарий опционален
4) Вернись в список и открой режим **“Проблемы”**.
5) Убедись, что заказ появился в списке со статусом `PARTIALLY_PICKED`, видна причина (и комментарий, если задан).
6) Нажми **“Открыть”**:
   - видны позиции/прогресс
   - виден аудит событий (SCAN_OK/SCAN_UNKNOWN/FINISH и т.п.)

## Offline

- При offline действия (скан/finish) блокируются.
- Экран “Проблемы” остаётся доступен только если backend доступен; иначе покажет ошибку загрузки.
